# Milestone 0 (M0) 工程骨架与基础通信链路实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 subagent-driven-development（推荐）或 executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 完成 Rust 1.99 + Python 3.13 (`uv`) 双语言工程骨架搭建，实现 Rust 宿主窗口秒开、Neutral Modern 深色主题、达芬奇 Dock 与 PR 分屏骨架，以及 Windows Job Object 内核级安全通信链路与命名管道双工 IPC。

**架构：** 根工程采用 Polyglot Monorepo，Rust 侧通过 Cargo Workspace 维护 6 个 crate，遵循严格的单向无环依赖图谱（`clipflow-common` -> `clipflow-timeline` / `clipflow-media` / `clipflow-ipc` -> `clipflow-ui` -> `clipflow-app`）；Python 侧由 `uv` 锁定 Python 3.13 虚拟环境；IPC 跨进程通信采用 Win32 Job Object（`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`）与异步双工命名管道（JSON-RPC 2.0 NDJSON），配合 Tokio 异步 stderr 排空消除 4KB 缓冲死锁。

**技术栈：** Rust 1.99, eframe 0.36, egui 0.36, wgpu 30.0, Python 3.13 (`uv`), Tokio, windows-sys (Win32 Job Object & Named Pipe), pytest, ruff, pwsh 7。

## 全局约束

1. 根目录通过 `.python-version` 严格锁定 Python 3.13，所有 Python 操作必须通过 `uv run` 执行，禁止全局 pip。
2. v1.0 MVP (M0~M2) 阶段禁止引入 `package.json` 或 Node.js 运行时依赖。
3. Rust Cargo Workspace crate 严格遵循 DAG 单向无环依赖，严禁跨层或反向依赖。
4. 全局禁止在时间基准中使用 `f32`/`f64`，所有时间计算必须采用 `RationalTime`（亚毫秒有理数时间）。
5. 错误处理严禁吞噬错误，Rust 库使用 `thiserror`，应用层严禁未说明原因的 `unwrap`/`expect`。
6. UI 严格遵循 Neutral Modern 深色规范：画布 `#0F1115`，面板 `#171A21`，钴蓝信号 `#2F6FEB`，圆角梯队 12/8/4px。
7. Windows 子进程必须以 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` 纳入内核作业对象，孤儿逃逸率严格为 0.0%。

## 审查重点（Review Focus）

1. **跨分母有理数运算溢出**：`RationalTime::rescaled_to` 处理超长时长与高采样分母（如 60000）相乘时可能溢出 `i64`，必须在乘法运算中使用 `i128` 中间暂存后再执行除法。
2. **Win32 Job Object 权限与句柄泄漏**：在某些受限环境或已有 Job 嵌套环境中，`AssignProcessToJobObject` 可能返回 `ERROR_ACCESS_DENIED`，必须配置 `JOB_OBJECT_LIMIT_BREAKAWAY_OK` 并在 `JobGuard` 的 Drop 特质中确保句柄安全释放。
3. **命名管道 MSVCRT 4KB 缓冲死锁**：Python Worker 向 `stderr` 输出大量 traceback 时，如果主进程未持续异步流式消费，OS 管道缓冲区（4KB）写满将导致 Python 进程永久挂起，必须由独立的 `AsyncStderrDrainer` 异步持续消费。
4. **JSON-RPC 换行符破坏分帧**：消息内容中含有换行符 `\n` 时可能导致 NDJSON 提前分帧解析失败，IPC 协议必须对 payload 换行符执行规范转义或单行严格序列化。
5. **帧网格吸附精度漂移**：`AgentTimelineAcl` 在处理浮点秒向帧对齐转换时，浮点截断可能导致 1 帧空洞，吸附算法必须采用最近邻四舍五入并强制边界重叠缝合。
